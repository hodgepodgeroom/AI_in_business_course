# Разработка по спецификациям

Текущее поведение продукта зафиксировано в [спецификации 001](001-demo-baseline/spec.md). [План и решения](001-demo-baseline/plan.md) объясняют устройство реализации. [Протокол проверки](001-demo-baseline/verification.md) связывает каждый критерий с результатом.

1. Сформулируйте пользовательский сценарий. Если изменение расширяет существующий сценарий, поправьте его спецификацию. Для самостоятельной возможности создайте каталог specs/NNN-название и скопируйте [шаблон](template.md).
2. В ветке feature укажите вход, ожидаемое поведение, обработку ошибок и критерии AC с наблюдаемым результатом. Опишите затронутые компоненты, контракты и последствия для ранее сохранённых заявок.
3. Реализуйте изменение. Для каждого критерия запишите команду проверки либо действия пользователя, исходные данные и фактический результат. Отдельно обозначьте симуляцию, внешний сервис и непроверенную часть.
4. Откройте pull request из feature в develop. При проверке сверьте реализацию со спецификацией и повторите затронутые проверки. Разногласия по ожидаемому поведению сначала разрешите в спецификации.
5. После приёмки переносите проверенную версию из develop в main. Перед следующей задачей обновите feature из develop. Все три ветки долгоживущие.

Изменение готово, когда другой разработчик может воспроизвести запуск, найти реализацию каждого требования и повторить приёмку. Незакрытый критерий отмечается в протоколе с причиной и конкретным способом проверки.
