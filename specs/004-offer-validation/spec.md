# 004 · Проверка условий покупки

* При подборе без ссылок проверяются известные источники в городе заявки и релевантная поисковая выдача. Прямые ссылки позволяют сравнить выбранные пользователем карточки.
* Размер упаковки, требуемое число упаковок и остаток рассчитываются кодом. Неоднозначные единицы и несовместимые фасовки исключают предложение.
* Тариф за партию применяется только при подтверждённых объёме и цене. Минимум 400 мешков исключает заявку на шесть. Стоимость партии нельзя умножать на число мешков.
* Розничная цена, требующая подтверждения, сохраняется с источником. В смете видно, сколько можно сэкономить, если магазин подтвердит цену. Ориентиры не участвуют в выборе.
* Для источников с публичным расчётом корзины проверяются товар, город и количество. Доставка и остатки без подтверждения остаются неизвестными.
* Проверка включает повторяемые эталонные заявки, сравнение с сохранёнными карточками и чтение действующего магазина.

## Как обработчик принимает решение

В запросе без ссылок обработчик объединяет найденные карточки с источниками для города. В комплекте есть каталог цемента для Казани и шесть карточек для Москвы. Известные адреса хранятся без цен. Если пользователь указал ссылки и по ним нашлось подходящее предложение, сравнение ограничивается этими карточками. Ссылки из поискового индекса и просроченная цена с явно подписанной розничной ценой показываются как ориентиры. При отсутствии подтверждённого варианта позиция остаётся открытой.

Код сверяет запрошенную фасовку с названием продаваемого варианта, ищет в нём однозначное количество и приводит граммы к килограммам, а миллилитры к литрам. Число покупаемых упаковок округляется вверх, остаток сохраняется в результате. Неоднозначные размеры упаковки требуют уточнения. В структурированных данных поддерживаются цена единицы, цена за явно заданное число продаваемых единиц и ограничения количества в единицах C62 или H87. На карточке с распознанным оптовым тарифом дополнительно сверяются цена единицы, минимум и сумма партии. Другие форматы могут потребовать адаптера поставщика.

Для каждого магазина смета сохраняет доступное основание цены. Противоречие между подписанной розничной ценой и разметкой требует уточнения. При выборе сравниваются подходящие корзины с известной доставкой, а при неполных данных показывается предварительная стоимость товара. Сумма товара по спорному предложению и возможная разница выводятся отдельно. Неизвестная региональная цена, наличие нужного количества и условия доставки выносятся в вопросы.

## Подключение источников

Следующие необязательные ключи добавляются в существующий объект `.local/agent.json`. После изменений перезапустите обработчик. Домены в примере условные.

```json
{
  "supplier_catalog": [
    {"city": "Москва", "name": "Валик ANZA Elite Титекс 250 мм", "url": "https://shop.example/roller-250"}
  ],
  "supplier_feeds": [
    {"city": "Москва", "url": "https://shop.example/catalog.yml"}
  ]
}
```

YML используется для поиска карточки по названию и городу. Цену обработчик перечитывает у поставщика. Загружаются публичные несжатые фиды до 2,5 МБ. Из одного фида за запрос проверяется до шести совпадений. Большой каталог можно подключить региональными или тематическими выгрузками.

В правило регионального магазина из [спецификации 003](../003-json-prices/spec.md) можно добавить объект `cart`, если поставщик публикует расчёт одной позиции методом GET. Полученный результат должен явно содержать SKU, регион, количество упаковок, валюту и сумму товара без доставки.

```json
{
  "cart": {
    "path": "/api/quote/{sku}?city={region}&packs={packs}",
    "fields": {
      "sku": "product.id", "region": "city", "packs": "quantity",
      "currency": "currency", "goods_total": "subtotal"
    }
  }
}
```

Если параметры или сумма расходятся, предложение переходит на уточнение. Успешная сверка подтверждает стоимость указанного количества одного товара. Доставку целой корзины, скидки между позициями и остатки этот метод не подтверждает. Все новые поля в интерфейсе необязательны для ранее сохранённых смет.

## Проверка

Команды из корня проекта:

```sh
python -m unittest discover -s services/agent
python tests/trial/check_offer_quality.py
python tests/trial/check_offer_quality.py --live
```

Последние две команды используют локальную Qwen по адресу из `OSNOVA_MODEL_API` или по умолчанию на порту 11436. Первый прогон эталонных заявок использует сокращённые карточки с зафиксированными ценами, второй читает сайты заново. Общий поиск отключён в обоих эталонных прогонах для сопоставимости. Для запроса без ссылок используется настоящий городской реестр. Изменение цены на сайте может дать расхождение с датированным эталоном.

Эталон проверяет выбранного поставщика, число покупаемых упаковок и сумму товара. Отдельно считаются случаи, когда пропущен доступный минимум, и случаи, когда рекомендованы недопустимый поставщик или неправильная фасовка. Это показатели контрольного набора.

### Результаты 18 ноября 2026 года

Локальная Qwen3.5-2B на CPU дала верный результат в 7 из 7 эталонных заявок как на сокращённых карточках, так и при чтении действующих магазинов. На этом наборе зафиксировано ноль пропущенных минимумов и ноль недопустимых рекомендаций. При отдельном повторе на полных сохранённых HTML-страницах пяти магазинов получен тот же результат сравнения для шести мешков. У реестра Москвы дополнительно проверили поиск валика без ссылки при недоступности общего поиска.

Системный DNS испытательной среды не разрешал часть внешних доменов. Только для сетевого прогона публичные A-записи получены через DNS по HTTPS. Проверены реальные карточки и локальная модель; запись тестовых заявок в очередь отключена. Настраиваемые YML-фид и расчёт корзины GET проверялись на тестовых ответах. При повторе позже в состоянии магазина, наличии и ценах возможны изменения.

Прошли 31 тест обработчика, 25 тестов автономного расчётного модуля, пять тестов веб-приложения, проверка типов TypeScript, ESLint и локальная сборка.
