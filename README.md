# Основа — закупка строительных материалов

Учебный прототип для прораба и закупщика. Пользователь указывает материалы, количество, город, адрес и срок. Локальный обработчик ищет предложения, сравнивает упаковки и готовит смету со ссылками. Согласование сохраняет решение в приложении. Заказ поставщику пользователь оформляет сам.

## Веб-приложение на Mac

Нужны Node.js 22.13 или новее и npm. Из корня репозитория выполните:

```sh
npm --prefix apps/web ci
npm --prefix apps/web run local
```

Откройте **http://127.0.0.1:5173**. Нажмите «Попробовать на примере» в форме, укажите город, адрес и срок и сохраните черновик. Для проверки очереди отправьте заявку на подбор. До подключения обработчика она останется в очереди. Остановка приложения — Ctrl+C. При следующем запуске вы снова увидите свои заявки.

В локальном режиме приложение создаёт SQLite-базу, файлы вложений и конфигурацию обработчика в `.local/` в корне репозитория. Это однопользовательский кабинет, привязанный к сетевому адресу этого компьютера. Вариант для размещения использует вход через доверенный шлюз, D1 и R2. [Архитектура и интерфейсы](docs/architecture.md)

## Подключение Qwen3.5

Для обработчика нужны Python 3.10 или новее и совместимый с Qwen3.5 сервер llama.cpp. Используйте уже загруженный GGUF либо скачайте текстовую квантизацию. Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r services/agent/requirements.txt
# При необходимости установить команду llama-server на Mac
brew install llama.cpp
# Если весов ещё нет, команда hf из huggingface_hub скачает один файл
hf download unsloth/Qwen3.5-2B-GGUF Qwen3.5-2B-Q4_K_M.gguf --local-dir models
```

Оставьте веб-приложение запущенным. Во втором терминале запустите сервер модели и обработчик одной командой:

```sh
.venv/bin/python services/agent/launch.py --model-file models/Qwen3.5-2B-Q4_K_M.gguf
```

Для существующего файла укажите его путь после `--model-file`. Имя файла может быть хешем без расширения. Параметр `--server /путь/к/llama-server` выбирает конкретный исполняемый файл, `--cpu` включает запуск на процессоре. При старте обработчик проверяет структурированный ответ модели. Его состояние видно в разделе «Подключение». Веса, исполняемый файл модели и ключ обработчика исключены из Git.

Если совместимый сервер уже работает, укажите имя обслуживаемой модели в поле `model` файла `.local/agent.json`, затем запустите только обработчик. Адрес задаётся переменной окружения:

```sh
OSNOVA_MODEL_API=http://127.0.0.1:11436/v1/chat/completions \
  .venv/bin/python services/agent/agent.py --config .local/agent.json
```

Инференс выполняется на компьютере. Для актуальных предложений обработчику нужен интернет. Поиск получает название материала и город, обработчик открывает карточки у поставщиков. Введите, например, «Цемент AKKERMANN М500 50 кг — 6 мешков» и укажите Казань. Ссылки необязательны. При наличии прямой ссылки её можно добавить отдельной строкой. Точную рублёвую цену обработчик читает из карточки, локальная модель проверяет товар и фасовку. Если магазин закрывает доступ, обработчик проверяет следующие результаты поиска. Цена из выдачи остаётся ориентиром. Фото и сканы без текстового слоя требуют уточнения. [Модель и варианты GGUF](https://huggingface.co/unsloth/Qwen3.5-2B-GGUF/tree/main)

## Учебный расчёт без модели и интернета

Для исходного сценария по ведомости работ в репозитории есть отдельный расчётный модуль. Он учитывает нормы, складские остатки, заказы и доставку. Запуск требует только Python:

```sh
python3 skills/prepare-construction-purchase/scripts/procurement.py run \
  --input skills/prepare-construction-purchase/assets/demo/input.json \
  --output-dir reports/demo
```

Откройте `reports/demo/report.html`. На учебных данных итог равен **12 440 ₽**, из них 500 ₽ за доставку. Статус `review_required` и восемь замечаний входят в ожидаемый результат. Рядом сохраняются JSON и четыре таблицы CSV.
